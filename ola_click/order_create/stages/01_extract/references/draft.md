# Order draft and checkout

## Keep the draft

- Resolve *"um de cada"* against the [saved menu offer](../../../../menu_read/stages/02_resolve_and_execute/tools/rules.md) actually shown. Use a [full catalog lookup](../../../../menu_read/stages/02_resolve_and_execute/tools/rules.md#expand-a-request-for-the-full-catalog) (`menu-offer.cjs catalog`) when explicitly asked for (or once the customer confirms) the entire menu. Never leave a collective placeholder such as *"um de cada produto do menu"* in `stage01_intent.json`; expand it into concrete items with verified `product_id`, `name`, `category_id`, and `description`, preserving the full catalog names and product order. If a typo leaves the scope unclear, confirm the likely reading, e.g. *"Quer dizer um item de cada do menu?"*
- For a continuation, use the latest `create_order` intent belonging to the open draft in this chat, including a draft with a preview orientation. Apply only the requested changes. An instruction to add a selection preserves earlier items and checkout details. On retry, start from the draft before this message so additions apply once. A menu lookup or recommendation leaves the draft intact. A completed order or an explicit basket replacement closes the preceding draft.

## Resolve choices

- An ordinal such as *"a primeira opção"* selects the first choice in the relevant list actually shown to the customer. Apply *"em todos"* only across groups with real, ordered choices. A numbered list of requirements such as *"pastel, molho, bebida"* does not specify any options.
- Record native selections by ID and verified prose selections in `catalog_review.groups[].selections`. Resolve ordinal phrases and placeholders before recording a selection. If a group has no choices shown, use verified options to offer a short shortlist or propose a fully specified combination for the customer to approve.
- Preserve the selections that are clear. Resolve each choice to its item and group. A standalone drink in the basket and a drink included in a menu are separate selections. For a reply such as *"Guaraná"* after a question about the Menu Estudante, fill that menu's drink only. If two open groups could apply to the answer, ask which item or group it belongs to.
- Use the [composite menu rules](menus_and_boxes.md) to distinguish included items from selectable ones. For a short order, ask the outstanding choices with their quantities in one message when practical. For many decisions, show a manageable group, naming the products, the missing amounts, and verified options, and end the reply with a direct question for that group. Continue with the remaining groups on the next turn. Never reply to an incomplete draft by only stating that choices are still missing without asking the next concrete question. Resolve all pending item choices and item confirmations (menus, boxes, modifiers, frozen items) before asking for service type (delivery vs. pickup), address/location, or checkout details. A generic request to confirm the basket does not resolve a pending choice.
- When a menu accepts a standard can, use current available cans from the catalog. Verify specific options, sizes, and eligibility when searching. When a product calls for a size or choice the catalog does not identify, flag the exact item for verification before accepting a selection.

## Check readiness

- Write the expanded draft to this message's `stage01_intent.json`. Always run the [draft check](../../02_resolve_and_execute/CONTEXT.md) (`check-draft.cjs`) before replying to an unfinished basket — never stop at `stage01_intent.json`. Use current catalogue reads to resolve product, variant and modifier details even when service details are missing. Treat invalid choices and unknown options as pending.
- Check published day restrictions against the requested service date in Europe/Lisbon. If an item is restricted, give the customer eligible alternatives or ask for an eligible date before attempting checkout.
- After a recommendation, add the item only when the customer asks. For delegated picks, let the customer approve the proposed specific choices before checkout.
- If quoting a subtotal before checkout, identify it as the current product subtotal. Use a verified checkout total when available. Tell the customer the order was placed only after a successful live creation with an order reference.
