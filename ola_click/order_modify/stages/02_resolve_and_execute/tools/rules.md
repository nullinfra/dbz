# Order modification — Tool rules

Use the modification intents and verified order records. In native MCP, the order UUID goes in `id`; item, payment and discount removals use the IDs of the entries on that order.

## Resolve the existing order

| Tool | Scope / kind | Required arguments | Optional arguments | When and how to use |
|---|---|---|---|---|
| [`get_orders`](https://developers.olaclick.app/docs/mcp#get_orders) | `orders:read` / read | — | `order_id` (string), `status` (string (`pending`, `preparing`, `ready`, `delivered`, `finalized`, `cancelled`)), `service_type` (string (`delivery`, `takeaway`, `onsite`, `table`)), `source` (string), `payment_status` (string), `payment_method_ids` (string), `owner_ids` (string), `rider_ids` (string), `delivered_by` (string), `delivery_status` (string), `is_scheduled` (string (`true`, `false`)), `client_id` (string), `public_id` (string), `cancelation_reason` (string), `start_date` (string), `end_date` (string), `start_time` (string), `end_time` (string), `time_type` (string), `timezone` (string (default `"America/Bogota"`)), `page` (integer ≥ 1), `per_page` (integer ≥ 1 ≤ 100) | Search orders by date, status, source or client. Supplying order_id bypasses filters and paging. Use lowercase status/service values. For today set both dates and Europe/Lisbon explicitly. |
| `get_order` | `orders:read` / read | `id` (UUID) | — | Read a single order and its combo, payment and discount IDs. Use the internal UUID, not the customer-facing order number. |

## Order changes and verification

| Tool | Scope / kind | Required arguments | Optional arguments | When and how to use |
|---|---|---|---|---|
| `update_order` | `orders:write` / write | `id` (UUID) | `comment` (string (max 500 chars)), `order_title` (string (max 50 chars)), `delivery_comment` (string (max 500 chars)), `delivery_price` (number ≥ 0), `packaging_price` (number ≥ 0), `scheduled_delivery_date` (string), `address_id` (UUID), `assigned_payment` (object or null) with {`payment_method_id` (UUID) required} | Patch an API order. comment appends. When changing a delivery address, verify client ownership and re-quote the fee. assigned_payment records intent to pay, and null clears it. |
| [`update_order_status`](https://developers.olaclick.app/docs/mcp#update_order_status) | `orders:write` / write | `id` (UUID), `status` (string (`PENDING`, `PREPARING`, `READY`, `DELIVERED`, `FINALIZED`)) | — | Advance only. Skipping steps applies intervening transitions. Use cancel_order for cancellation. |
| [`cancel_order`](https://developers.olaclick.app/docs/mcp#cancel_order) | `orders:write` / write | `id` (UUID), `reason` (string (`REJECTED_ORDER`, `TEST_ORDER`, `WRONG_ORDER`, `FREE_ORDER`, `DUPLICATED_ORDER`, `OTHER`)) | `detail` (string (max 200 chars)) | Cancel an API order with no active payments. Use detail for OTHER. Check the order and handle any authorised payment reversal first. |
| [`add_order_combos`](https://developers.olaclick.app/docs/mcp#add_order_combos) | `orders:write` / write | `id` (UUID), `combos` (array of object (1–unbounded items)) with {`variant_id` (UUID) required, `quantity` (integer ≥ 1) required, `comment` (string (max 500 chars)), `modifiers` (array of object (default `[]`)) with {`modifier_id` (UUID) required, `quantity` (integer ≥ 1 (default `1`))}} | — | Build lines from verified variants. Send the basket together. Each modifier quantity is per unit of its combo. Read get_product for required modifier groups and limits. |
| `remove_order_combo` | `orders:write` / destructive | `id` (UUID), `comboId` (UUID) | — | Remove an active order line. comboId comes from get_order and differs from a catalogue product or variant ID. |
| [`add_order_payment`](https://developers.olaclick.app/docs/mcp#add_order_payment) | `orders:write` / write | `id` (UUID), `payment_method_id` (UUID), `bill_amount` (number > 0) | `received_amount` (number ≥ 0), `tip_amount` (number ≥ 0) | Register money actually collected. Get the method ID from list_payment_methods and check service eligibility. bill_amount is the charge, received_amount is what was tendered. |
| `remove_order_payment` | `orders:write` / destructive | `id` (UUID), `paymentId` (string) | — | Cancel a recorded payment by its payment ID. Verify the remaining balance and follow the separate process for any external refund. |
| `add_order_discount` | `orders:write` / write | `id` (UUID), `type` (string (`AMOUNT`, `PERCENTAGE`)), `value` (number > 0) | `description` (string (max 100 chars)) | Apply a manual discount using the specified currency amount or percentage, as requested. Re-read the totals. |
| `remove_order_discount` | `orders:write` / destructive | `id` (UUID), `discountId` (string) | — | Remove a recorded discount or applied coupon using the discount entry ID from get_order. |
| [`apply_order_coupon`](https://developers.olaclick.app/docs/mcp#apply_order_coupon) | `orders:write` / write | `id` (UUID), `code` (string (max 191 chars)) | — | Apply the redeemable code to an order with a client attached. Verify the resulting discount and totals. |

- **Order lookup and update.** Locate a public order number with `get_orders` using `order_id`, then use the returned UUID as `id` in `get_order` and order writes. For a prepared delivery address, quote the fee before `create_order` or `update_order`. If a basket submission is interrupted, inspect its lines before adding any again.
- **Order items.** In `add_order_combos`, use `combos: [{"variant_id":"<variant UUID>","quantity":2,"modifiers":[{"modifier_id":"<modifier UUID>","quantity":1}]}]`. That records one modifier per unit, two in total. Product `id`, variant `variant_id` and order line `comboId` identify three different records.
- `get_orders` currently advertises singular `service_type` with lowercase values; its prose mentions plural `service_types`, which is absent from the live argument list. For several service types, make one filtered read per type and merge by order UUID.
