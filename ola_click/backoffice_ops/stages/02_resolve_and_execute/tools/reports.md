# Back-office reports — Tool rules

Load for sales, dashboard or cash register requests. Use the ICM report type for supported workflows. Use `YYYY-MM-DD` for report dates and `HH:mm:ss` for time filters. Send `Europe/Lisbon` when requesting the local reporting period.

The usual `sales_summary` read calls `get_orders_summary` with all valid sources and `timezone: "Europe/Lisbon"`. When `include_top_products: true`, it runs `get_products_sold` in parallel and attaches `top_products` to `sales_summary`. Select the tool that returns the requested measure: sales totals, order counts by source, menu conversions and product margins describe different outcomes.

Defaults to the last seven days without a start date. Use include for product, modifier or freehand grouping. |
| `get_menu_visits_today` | `reports:read` / read | — | `timezone` (string) | Read today’s digital menu visit count in the chosen timezone. |
| `get_menu_performance` | `reports:read` / read | `end_date` (string), `start_date` (string) | `timezone` (string) | Compare menu visit, cart and order counts over the date range and preceding equal-length period. |
| `get_menu_conversion` | `reports:read` / read | `end_date` (string), `start_date` (string) | `timezone` (string) | Read cart and order conversion rates over the date range, with the previous period for comparison. |
| `get_orders_summary` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Read order count, sales and average ticket, with previous-period comparison. Pass all permitted sources for a company-wide result. |
| `get_orders_by_service_type` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Compare order count, sales and average ticket by service type. |
| `get_orders_by_source` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Read order counts per source; this is not a sales revenue breakdown. |
| `get_orders_by_delivery_method` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Read order counts per delivery actor. Orders without one are omitted. |
| `get_top_payment_methods` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Rank method usage by number of payments. |
| `get_sales_evolution` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Compare daily order counts with the previous period. Values are counts. |
| `get_sales_by_hour` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Read order counts in two-hour slots. |
| `get_sales_by_day` † | `reports:read` / read | `start_date` (string), `end_date` (string), `sources` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`created_at`, `pending_at`, `closed_at`)), `timezone` (string) | Read order counts by day of the week. |
| `get_margins_summary` † | `reports:read` / read | `start_date` (string), `end_date` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`client_ticket_printed_at`, `closed_at`, `created_at`, `delivery_status_updated_at`, `pending_at`, `prepared_at`, `preparing_at`, `scheduled_delivery_date`, `updated_at`)), `category_ids` (string), `include` (string (`products`, `products_modifiers`, `freehand`)), `combo_type` (string (`FREEHAND_WEIGHT`, `FREEHAND_UNIT`)), `show_products` (integer), `service_types` (string), `timezone` (string) | Read overall margins, excluding products with no configured cost. The formula is average sale price / average cost − 1. |
| `get_product_margins` † | `reports:read` / read | `start_date` (string), `end_date` (string) | `start_time` (string), `end_time` (string), `time_type` (string (`client_ticket_printed_at`, `closed_at`, `created_at`, `delivery_status_updated_at`, `pending_at`, `prepared_at`, `preparing_at`, `scheduled_delivery_date`, `updated_at`)), `category_ids` (string), `include` (string (`products`, `products_modifiers`, `freehand`)), `combo_type` (string (`FREEHAND_WEIGHT`, `FREEHAND_UNIT`)), `show_products` (integer), `service_types` (string), `timezone` (string), `per_page` (integer), `page` (integer) | Page through sold products with cost and margin data. A variant without configured cost is omitted from the margin calculation. |

## Cash registers

| Tool | Scope / kind | Required arguments | Optional arguments | When and how to use |
|---|---|---|---|---|
| `list_cashiers` | `cashiers:read` / read | — | — | Resolve cash register IDs and whether each register is open. These IDs are distinct from staff UUIDs. |
| `list_cashier_balances` | `cashiers:read` / read | — | `per_page` (number), `page` (number), `timezone` (string), `end_date` (string), `start_date` (string), `cashier_id` (string), `status` (string) | Page through openings and closings. Supply both date bounds if filtering by date. |
| `get_cashier_balance` | `cashiers:read` / read | `id` (UUID) | — | Read one register session balance and its payment-method breakdown. |

- **Sales reports.** Send at least `start_date`, `end_date` and `sources` to the order-count and sales tools that require sources. `sources` is one comma-separated string. For all sources advertised by these schemas use `CHATBOT,DIDI,IFOOD,INBOUND,99FOOD,OUTBOUND,PEDIDOSYA,RAPPI,RAPPI_TURBO,UBER_EATS,KEETA,TOTEM,QR,API`.
