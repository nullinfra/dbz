# Promotions — Resolution policy

Resolve promotion names and codes to verified IDs before get, update or delete. Check scopes, dates, discount value and eligibility from the request. For a product-specific promotion, verify every target against the live catalogue before constructing the API request and preserve the selected product IDs and names. A missing target requires a new selection.

Explicit owner creation or update requests execute directly under `run-stage02.cjs` (respecting the environment's `OLACLICK_ALLOW_WRITES` setting; do not pause to ask the user for confirmation unless `orientation.json` returns `NEEDS_CONFIRMATION`). Only deletion requires both write and destructive confirmation: on an initial delete request (before the owner replies confirming a prior deletion prompt), run `OLACLICK_ALLOW_DESTRUCTIVE=0 node ola_click/_shared/tools/run-stage02.cjs --summary "$ola_out"` so `orientation.json` returns `NEEDS_CONFIRMATION` and you ask the owner to confirm. An existing promotion may have terms that affect a partial update. Read those terms before deciding whether an edited field is valid in context.
